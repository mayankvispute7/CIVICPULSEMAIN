# Demo Data Dictionary

This document defines the synthetic/demonstration universe generated by `seed_db.py`.

## Provenance Labels
All data is explicitly tagged using the `DataTruth` enum:
- `REAL_DATA`: Actual municipal records (Not used in the demo seed).
- `IMPORTED_DATA`: Initial complaint records mimicking CSV ingestion.
- `SYNTHETIC_DATA`: AI/script-generated context (e.g. historical timeline).
- `MODEL_ESTIMATION`: Algorithmically derived parameters (e.g., 5-year predictions, capacity ratios).
- `ASSUMPTION`: Hardcoded defaults (e.g., constraints).

## The Primary Case
**ID Structure:** UUID generated by `generate_uuid()`
**Title:** Recurring Waterlogging
**Location:** Kothrud-Bavdhan

### Linked Entities
1. **Complaints (18 records):** Tagged as `IMPORTED_DATA`. Represents citizens reporting waterlogging over 5 days.
2. **Evidence (6 records):** 
   - Complaint concentration (`IMPORTED_DATA`)
   - Rainfall correlation (`SYNTHETIC_DATA`)
   - Terrain (`SYNTHETIC_DATA`)
   - Drainage Capacity (`MODEL_ESTIMATION`)
   - Historical recurrence (`SYNTHETIC_DATA`)
   - Previous intervention (`SYNTHETIC_DATA`)
3. **Historical Incidents (4 records):** `SYNTHETIC_DATA`. Two are fully detailed (2024 drain cleaning, 2025 return of accumulation).
4. **Prediction (1 record):** `MODEL_ESTIMATION`. "Do Nothing Baseline" indicating a high 5-year exposure risk.
5. **Interventions (8 records):** Generated dynamically by `InterventionEngine`.
6. **Work Order (1 record):** Maps to the selected "Drain Repair" intervention.
7. **Tasks (2 records):** Site Inspection, Drain Repair.
8. **Replan Event (1 record):** Triggered by "1 worker unavailable due to illness."
9. **Field Evidence (1 record):** `SYNTHETIC_DATA` linking a mock `/demo/verification.jpg`.
10. **Outcome (1 record):** `SYNTHETIC_DATA`. Drops complaints from 18 to 6 during the "next comparable rain event."
11. **Memory (1 record):** Summarizes the full lifecycle and extracts "Drain repair effectively handles standard rainfall events."
